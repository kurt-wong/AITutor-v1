# 文档治理规则 (Document Governance Rules)

> 生效日期: 2026-07-12 | 版本: 1.0

---

## 1. 文档权威层级

当文档间存在冲突时，优先级如下：

```
TASK.md > MIS.md > ACS.md > SAD.md > PRD.md > DSD.md > Project Rules > 全局规则
```

---

## 2. 文档修改规则

### 2.1 必须先验证代码

任何文档描述的**技术实现细节**（MCP 工具列表、类名、文件名、API 端点、表结构）在写入文档前，必须通过 `scripts/validate_docs_vs_code.py` 验证。

### 2.2 文档-代码同步原则

- **代码变更必须同步文档**: 新增/修改 MCP 工具 → 更新 MIS.md 和 PRD.md §4
- **文档变更必须验证代码**: 文档声称某个功能已实现 → 验证代码实际存在
- **禁止"目标架构"与"实现架构"混淆**: 文档必须清楚标注 [已实现] 或 [计划中]

### 2.3 版本号规则

| 变更类型 | 版本号变化 |
|---------|-----------|
| MCP 工具新增/删除 | MINOR++ (1.5 → 1.6) |
| 架构重大变更 | MAJOR++ (2.0 → 3.0) |
| 错字/格式修正 | PATCH (2.0 → 2.0.1) |

---

## 3. 文档修改流程

```
1. RFC 文档（Docs/06_RFC/）描述变更意图
2. 代码实现 + 测试
3. 运行 validate_docs_vs_code.py 确认一致性
4. 更新受影响文档 + 版本号
5. 更新 CHANGE LOG
6. 合并（代码 + 文档一起提交）
```

---

## 4. 保护机制

### 4.1 ARCHIVE 备份

每次大规模文档修正前，备份到 `Docs/ARCHIVE/<YYYY-MM-DD>/`。

### 4.2 验证脚本

```bash
cd backend && .venv/Scripts/python.exe scripts/validate_docs_vs_code.py
```

退出码 0 = 文档与代码一致。CI 中应包含此检查。

### 4.3 禁止事项

- ❌ 文档中声称不存在的文件/类/方法
- ❌ 文档中声称不存在的 MCP 工具
- ❌ 使用与实际代码不符的前端页面名称
- ❌ "目标架构"不加标记地与"实现架构"混写
- ❌ 跳过验证脚本直接修改文档中的技术细节
